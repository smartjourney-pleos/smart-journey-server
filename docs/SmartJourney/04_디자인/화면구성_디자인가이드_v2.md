# 스마트 저니 프로토타입 화면 구성 v2 (디자이너 전달용)

> 수정일: 2026-11-10 · 기준 문서: 개발 명세서 v3.1, 공모전 접수양식
> 목적: 2차 PT(12/3–12/4) 라이브 데모와 시연 영상에 쓸 프로토타입 화면을 그리기 위한 화면·요소 목록
> 범위: ① 차량 앱(Pleos Connect 인포테인먼트) ② 매장 점주용 웹 POS(태블릿)

**v1에서 크게 바뀐 점**
- 스마트 저니는 **앱 화면을 열어 두고 쓰는 앱이 아니라, 플레오스 내비 뒤에서 도는 앱**입니다. 운전자는 평소처럼 내비를 보며 가고, 앱은 결정이 필요한 순간에만 잠깐 나타납니다.
- 그래서 디자인의 주인공은 앱 안 화면이 아니라 **내비를 쓰는 중에 뜨는 것들**(상태 알림 한 줄, 승인 카드, 결과 알림, 음성 표시)입니다. 작업 순서도 이쪽이 먼저입니다(0.6절).
- **지도는 그리지 않습니다.** 지도와 길 안내는 플레오스 내장 내비가 그대로 보여 줍니다.

---

## 0. 먼저 읽어 주세요

### 0.1 서비스 한 줄
플레오스 내비 뒤에서 돌면서, 차가 탑승 인원·도착·하차를 확인해 맛집 원격 웨이팅을 대신 걸어 주는 차량용 앱. 운전자는 운전 중에 승인 한 번(터치 또는 음성)만 하면 되고, 앱을 직접 열 일은 거의 없습니다.

### 0.2 화면에 나오는 사람
| 사용자 | 기기 | 주로 보는 것 |
| --- | --- | --- |
| 운전자 | 차량 중앙 디스플레이 | 내비 + 그 위에 잠깐 뜨는 승인 카드, 음성 |
| 동승자 | 차량 중앙 디스플레이 (정차 중) | 처음 한 번: 방문지 고르기, 인원 확인, 여정 시작 |
| 매장 점주 | 태블릿 웹 POS (가로) | 대기 팀 관리, 도착·하차 확인, 호출 |
| 심사위원 (데모) | 태블릿 POS 데모 패널 | 대기 팀 수를 바꿔서 차량 반응 보기 |

### 0.3 앱이 화면에 나타나는 3가지 방식 ★ 가장 중요

| 층 | 언제 | 무엇이 보이나 | 시안에서 그릴 것 |
| --- | --- | --- | --- |
| ① 뒤에서 도는 중 | 여정 시작 후 대부분의 시간 | 내비 화면 그대로 + **상태 알림 한 줄** ("A 맛집 · 웨이팅 알림까지 12분") | N-01 상태 알림 |
| ② 결정이 필요한 순간 | 골든타임, 지연, 도착·하차, 호출, 인원 변동 | 내비 위에 **카드 1장** 또는 **음성** | V-07 ~ V-12 (접점) |
| ③ 사용자가 직접 열 때 | 정차 중 처음 설정, 진행 상황 확인 | 앱 전체 화면 | V-00 ~ V-06, V-13, V-14 |

- 카드는 **내비를 완전히 덮지 않는 것이 원칙**입니다. 운전 정보 영역과 지도는 보이게 두고, 앱 영역에만 뜹니다.
- 카드가 실제로 어떤 모양으로 뜰지(전체 카드 / 상단 배너 / 음성만)는 개발에서 **11/12까지 플레오스 에뮬레이터로 확인**합니다. 그 전까지는 세 가지 모양을 모두 그려 주세요(2장 C-04 변형 참고).

### 0.4 Pleos 화면 구조 전제 (공식 가이드 기준)
- 화면 한쪽에는 **운전 정보 영역(Driving view)이 항상 고정**돼 있고, 앱은 나머지 앱 영역만 씁니다.
- 앱 영역은 차종에 따라 **창 1개 또는 2개**입니다. 앱은 **세로(창 1개)**가 기본이고, 가로로 설정하면 창 2개를 이어서 씁니다.
- 사용자가 창 크기를 바꿀 수 있으니 **크기가 줄어도 깨지지 않는 레이아웃**이 필요합니다.
- 정확한 해상도와 비율은 Pleos Playground의 디자인 리소스(Display Layout, Download Design Resources)에서 받아 프레임을 잡아 주세요. 이 문서에서는 픽셀 값을 정하지 않습니다.
- Pleos UI 디자인 가이드의 아이콘, 용어, 인터랙션 패턴을 따라 순정 UI와 어색하지 않게 맞춥니다.
- **내비 배경:** 접점 프레임 뒤에 깔 내비 화면은 플레오스 에뮬레이터 캡처를 쓰거나 회색 플레이스홀더로 둡니다. 우리가 지도를 새로 그리지 않습니다.

### 0.5 주행 중 디자인 원칙 (심사 통과 조건)
| 원칙 | 적용 |
| --- | --- |
| 앱을 열게 만들지 않기 | 주행 중 필요한 정보는 상태 알림 한 줄과 카드로 끝냄. "앱에서 확인하세요" 같은 유도 금지 |
| 주행 중 입력 금지 | 검색, 키보드, 설정, 코스 편집, 인원 수정은 **정차 중에만**. 주행 중엔 잠금 상태 디자인 필요 |
| 한 번에 판단 | 주행 중 카드는 **카드 1장, 문장 2줄 이내, 버튼 최대 2개** |
| 큰 터치 타깃 | 버튼은 크게, 터치 영역은 버튼보다 조금 더 넓게 |
| 고대비 · 최소 텍스트 | 큰 글자, 숫자 강조, 장식 최소 |
| 애니메이션 없음 | 주행 중에는 움직이는 효과를 쓰지 않음 (정차 중엔 가벼운 전환만) |
| 음성 우선 | 모든 주행 중 카드에 **"말로 하기" 상태 표시**(Gleo 듣는 중) 포함 |
| 다국어 확장 | 한국어 기준으로 그리되 문구가 1.5배 길어져도 버틸 수 있게 여유 |

### 0.6 작업 우선순위
| 순서 | 묶음 | 화면 | 이유 |
| --- | --- | --- | --- |
| 1 | 접점 컴포넌트 | N-01 상태 알림, C-04 승인 카드(3가지 모양), C-17 결과 알림, C-10 음성 표시 | 시연의 핵심 장면이 전부 여기서 나옴 |
| 2 | 핵심 접점 화면 | V-07 골든타임, V-10 하차 확인, V-08 접수 완료, V-11 호출 | PT 흐름 5·8·10번 |
| 3 | POS | P-02 대기열 보드, P-06 데모 패널 | 심사위원이 직접 만지는 화면 |
| 4 | 정차 설정 흐름 | V-02 → V-03 → V-04 → V-05 → 여정 시작 | 시연 처음 1분 |
| 5 | 나머지 | V-06, V-09, V-12 ~ V-17, 예외, 가로 시안 | 여유 있을 때 |

### 0.7 산출물 체크리스트
- [ ] 접점 프레임: **내비 배경 + 상태 알림 / 카드** 합성 화면 (세로 기준, 핵심 3장은 가로도)
- [ ] 공통 컴포넌트 라이브러리 (상태 알림, 승인 카드 3변형, 결과 알림, 상태 배지 등)
- [ ] 정차 중 앱 화면: 세로 + 가로(주요 화면만)
- [ ] POS 화면: 태블릿 가로
- [ ] 상태별 변형(빈 상태, 로딩, 오류, 연결 끊김)
- [ ] PT 시연 흐름 순서대로 이어 붙인 프로토타입 (9장)
- [ ] 다크 / 라이트 중 Pleos 기본 테마에 맞춘 1종 (가능하면 2종)
- [ ] 그리지 않는 것: 지도, 길 안내 화면, 앰비언트 라이트, 미니 지도(P2 선택 기능)

## 1. 전체 화면 지도

```
[차량 앱]

A. 내비 위에 뜨는 접점 (주행·도착 중, 앱을 열지 않은 상태) ★ 우선
   N-01 상태 알림 한 줄 (여정 내내)
   V-07 골든타임 승인 카드 → V-08 접수 완료
   V-09 도착 지연 대응 카드
   V-10 도착·하차 확인 (도착 시)
   V-11 호출됨 · 번호표
   V-12 다음 매장 인원 변경 제안 (재출발 전)

B. 정차 중 사용자가 여는 앱 화면
   V-00 시작·지원 확인
    └ V-01 데이터 전송 동의 (첫 실행)
        └ V-02 홈
            ├ V-03 탑승 인원 확인
            ├ V-04 방문지 고르기
            │   └ V-05 코스 확인 → [여정 시작] → V-05b 시작 완료 (앱이 뒤로 빠짐)
            ├ V-06 여정 진행 현황 (확인용)
            │   └ V-13 웨이팅 상세 / 취소
            └ V-14 설정

C. 예외·보조
   V-15 주행 중 잠금 / 연결 끊김 / 센서 미지원 / 서버 오류
   V-16 주행 중 앱을 열었을 때 미니 화면
   V-17 데모용 신호 조작 패널 (개발·시연 백업)

[매장 POS]
P-01 로그인 → P-02 대기열 보드
                ├ P-03 팀 상세 패널
                ├ P-04 호출 / 착석 / 노쇼 확인
                ├ P-05 매장 설정
                └ P-06 데모 패널
P-07 연결 끊김 / 빈 상태
```

| C-03 | 연결 상태 배너 | "서버와 연결이 끊겼어요. 다시 연결하는 중…" | 끊김 / 재연결 완료 |

| C-14 | QR 번호표 | 번호(크게), QR, 매장명, 인원 | 활성 / 만료 |

## 3. 차량 앱 화면 상세

각 화면마다 **목적 / 들어오는 조건 / 화면 요소 / 상태 변형 / 주행 중 동작**을 적었습니다.

### A. 내비 위에 뜨는 접점 ★

#### N-01 상태 알림 한 줄
- **목적:** 앱을 열지 않아도 "지금 어떤 상태인지"를 한 줄로
- **들어오는 조건:** 여정 시작(V-05b) 후 여정이 끝날 때까지 계속
- **요소:** 앱 아이콘, 매장명, 상태 문장, 큰 숫자 하나. 누르면 정차 중일 때만 V-06이 열림
- **변형 문구:**
  - 알림 대기: "A 맛집 · 웨이팅 알림까지 12분"
  - 접수됨: "A 맛집 · 앞에 3팀 · 도착 18분 후"
  - 도착 확인 중: "A 맛집 · 내리는 인원 확인 중"
  - 호출됨: "A 맛집 · 입장하세요"
  - 정확도 낮음 / 연결 끊김: 문장 뒤에 C-15 또는 끊김 아이콘
- **주행 중:** 그대로 표시, 누르면 반응 없음(또는 V-16)

#### V-07 골든타임 승인 카드 ★ 핵심
- **목적:** 지금 웨이팅을 걸지 한 번에 결정
- **들어오는 조건:** 남은 시간이 (예상 대기 − 도착 여유) 이하가 됨. 앱은 뒤에 있는 상태
- **요소:**
  - 매장명 "A 맛집"
  - 큰 숫자 줄: "4명 · 대기 30분 · 도착 20분 후"
  - 질문: "지금 웨이팅 걸까요?"
  - 버튼: [등록] (주, 크게) [나중에]
  - 음성 표시 C-10: "'등록해 줘'라고 말해도 돼요"
  - 자동 닫힘: 남은 초 숫자 (주행 중엔 진행 바 애니메이션 대신 숫자)
- **모양 3종(C-04):** ⓐ 앱 영역 전체 카드 ⓑ 상단 배너형 ⓒ 음성 전용. **세 장 모두 내비 배경 위에 합성해서** 그려 주세요
- **변형:** 기본 / 대기가 짧아 바로 띄움("대기가 짧아요") / 음성 인식 중 / 인식 실패("다시 말해 주세요") / 처리 중(버튼 로딩)
- **결과:** 성공 → V-08 / 실패 → "등록하지 못했어요. 다시 시도할까요?" [다시] [건너뛰기]. 카드가 닫히면 바로 내비 화면만 남음

#### V-08 접수 완료
- **형태:** C-17 결과 알림 (카드가 아니라 3초짜리 알림)
- **요소:** 체크 아이콘, "A 맛집 4명 등록했어요 · 앞에 3팀", 예상 입장 시각
- **음성:** "A 맛집에 4명으로 등록했어요. 앞에 3팀 있어요."
- **이후:** N-01이 "접수됨" 문구로 바뀜

#### V-09 도착 지연 대응 카드
- **목적:** 정체로 늦어질 때 순번 미루기 / 다른 매장 먼저 가기
- **요소:** "도착이 15분 늦어질 것 같아요", [순번 한 번 미루기] [그대로 두기]. 다른 매장 먼저 가기는 별도 카드("B 카페를 먼저 갈까요?")
- **변형:** 미루기 가능 / 미루기 횟수 다 씀("더 미룰 수 없어요") / 다른 매장 먼저 제안
- **주의:** 버튼 2개 원칙 유지. 우선순위 낮은 기능이라 기본 모양 ⓐ 하나만 있어도 됨

#### V-10 도착·하차 확인 ★ 핵심 차별 기능
- **목적:** 차가 도착과 하차 인원을 확인해 매장에 보내는 과정 보여 주기
- **들어오는 조건:** 내비가 매장 도착을 알림 → 차가 멈춤. 앱이 알아서 카드로 뜸 (정차 상태라 카드가 조금 더 커도 됨)
- **단계별 상태(같은 카드의 변화):**
  1. 도착: "A 맛집에 도착했어요"
  2. 확인 중: 좌석 도식에서 빈 좌석이 하나씩 꺼짐, "내리는 인원 확인 중…" (체크리스트: 정차 ✓, 문 열림 ✓, 좌석 변화 …)
  3. 확정: "3 / 4명 하차 확인 · 매장에 알렸어요" + 운전자 안내 "주차하고 따라가세요" + **입장 번호 미리 보여 주기**(열린 질문 1)
  4. 수동 전환(3분 초과 또는 센서 문제): "자동으로 확인하지 못했어요" + [도착했어요] 큰 버튼
  5. 미확인 전송: "도착만 알렸어요(인원 미확인)"
- **요소:** C-13 하차 인디케이터, 진행 체크리스트, 매장 전송 상태
- **문구 주의:** 인원 수 확인이지 신원 확인이 아님 → "몇 분이 내렸는지만 확인해요"

#### V-11 호출됨 · 번호표
- **형태:** C-17 결과 알림(짧게) + 누르면 번호표 카드
- **요소:** "입장하세요!" 큰 제목, C-14 QR 번호표(번호 크게), 매장명, 인원
- **주의:** 일행은 이미 내린 뒤라 차 화면을 못 볼 수 있음 → 번호를 크게, V-10 확정 단계에서 미리 보여 주기

#### V-12 다음 매장 인원 변경 제안
- **들어오는 조건:** 식사 후 재탑승, 출발 직전 좌석 수가 다음 매장 접수 인원과 다름 (정차 상태)
- **요소:** "B 카페 인원을 3명으로 바꿀까요?", "4명 → 3명", [바꾸기] [그대로]
- **변형:** 변경 실패("이미 호출돼서 바꿀 수 없어요")

### B. 정차 중 사용자가 여는 앱 화면

#### V-00 시작·지원 확인
- **목적:** 앱 실행 시 좌석·도어 센서와 내비 연동 지원 여부 확인
- **요소:** 로고, 짧은 로딩, 확인 항목 3개(좌석 센서, 도어 센서, 내비 연동) 체크
- **변형:** 모두 지원 / 일부 미지원("좌석 센서를 쓸 수 없어 인원을 직접 입력해요") / 실패

#### V-01 데이터 전송 동의 (첫 실행)
- **요소:** 제목 "매장에 이런 정보만 보내요", 항목 리스트(인원 수, 하차 인원 수, 도착 예상 시간(분), 도착 여부, 웨이팅 정보), 강조 "위치 좌표와 이동 경로는 보내지 않아요", 받는 곳(스마트 저니 서버, 웨이팅한 매장), [동의하고 시작] [나중에], "설정에서 언제든 철회할 수 있어요"
- **변형:** 미동의 상태에서 기능 진입 시 다시 띄움

#### V-02 홈
- **목적:** 여정 만들기 시작점
- **요소:** 인사 한 줄, "오늘의 탑승 인원 N명" 요약, [방문지 고르기] 주 버튼, 최근 방문 매장 2~3개
- **변형:** 여정 없음(빈 상태) / 진행 중 여정 있음(→ V-06)

#### V-03 탑승 인원 확인
- **요소:** 좌석 도식(C-13 재사용, 벨트 상태 포함), 큰 숫자 "4명" + "좌석 센서로 확인했어요", C-07 스테퍼, 안내 "짐이 사람으로 잡힐 수 있어요. 다르면 고쳐 주세요" / "어른·아이는 구분하지 않아요", [이 인원으로 할게요]
- **변형:** 센서값 / **짐 의심 좌석 표시**("1자리는 확인이 필요해요", 벨트를 안 맨 좌석) / 직접 수정 / 센서 미지원 / 값 불안정("좌석 확인 중")

#### V-04 방문지 고르기
- **요소:** 매장 리스트(C-05), 선택 체크, 하단 선택 바("2곳 선택 · 최대 3곳") + [다음]
- **데모 메모:** 가상 매장 2~3곳 고정 리스트로 충분. 검색창은 시안만

#### V-05 코스 확인 → V-05b 시작 완료
- **목적:** 방문 순서를 정하고 내장 내비에 넣은 뒤, 앱은 뒤로 빠짐
- **요소:** C-09 타임라인(출발 → A 맛집 → B 카페), 지점별 예상 대기, 순서 바꾸기(위/아래 버튼 또는 드래그), [여정 시작]
- **순서 제안:** 자동 순서 제안은 보조 기능입니다. 기본 화면은 **고른 순서 그대로 + 사용자가 바꾸기**로 그리고, "추천 순서" 표시는 변형으로만 그려 주세요
- **V-05b (신규):** "내비에 경로를 넣었어요. 이제 앱을 닫아도 돼요. 웨이팅할 때가 되면 알려 드릴게요." → 2초 뒤 앱이 닫히고 내비 + N-01만 남는 장면까지
- **변형:** 내비 입력 실패("내비에 넣지 못했어요 [다시]") / 영업 종료 매장 제외 표시

#### V-06 여정 진행 현황 (확인용)
- **위상 변경:** v1의 "메인 대시보드"가 아니라, **N-01을 눌렀을 때 정차 중에만 열리는 확인 화면**입니다
- **요소:** 탑승 인원, 현재 매장 카드(상태 배지, C-08 시간 블록: 도착까지 / 예상 대기 / 웨이팅 알림까지), 다음 매장 작은 카드, 접수 후엔 순번·앞 팀 수·예상 입장 시각. 가로는 전체 타임라인 + 이벤트 로그 추가
- **변형:** 알림 대기 / 접수됨 / 도착 확인 중 / 호출됨 / 완료 / 정확도 낮음 / 연결 끊김 / [여정 끝내기]

#### V-13 웨이팅 상세 / 취소
- **요소:** 매장 정보, 접수 번호, 순번, 인원, 이벤트 기록, [순번 미루기] [웨이팅 취소], 취소 확인 다이얼로그

#### V-14 설정
- **항목:** 도착 여유 시간(기본 10분, 5~20분), 음성 안내 켜기/끄기, 데이터 전송 동의 상태 + [동의 철회], 앱 정보, (개발용) 데모 모드

## 8. 인터랙션·접근성 메모

- 승인 카드가 뜰 때: 정차 중엔 짧은 전환, **주행 중엔 전환 없이 바로 표시**
- 카드는 60초 무응답이면 닫히고 "나중에" 처리 → N-01 문구로 돌아감
- 카드가 닫히면 **항상 내비 화면으로 돌아감** (앱 화면으로 가지 않음)
- 모든 숫자에 단위 표시 ("20분", "4명", "3팀")
- 터치 영역과 버튼 간격 넉넉하게, 아이콘만 있는 버튼 금지
- 창 크기가 줄었을 때 우선순위: 매장명 > 상태 > 큰 숫자 > 버튼 > 부가 정보

## 9. PT 시연용 프로토타입 흐름 (이 순서로 프레임 연결)

**정차: 처음 1분**
1. V-02 홈 → V-03 "탑승 인원 4명"
2. V-04 A 맛집 + B 카페 선택 → V-05 코스 확인 → [여정 시작]
3. V-05b "이제 앱을 닫아도 돼요" → **앱이 사라지고 내비 + N-01만 남는 장면** ("A 맛집 · 웨이팅 알림까지 20분")

**주행: 앱은 뒤에서 돎**
4. **POS P-06에서 심사위원이 현장 대기 팀 +3** → **N-01 숫자가 바로 바뀜** (앱을 열지 않은 상태)
5. 내비 위에 V-07 골든타임 카드 → 음성 "응, 걸어 줘" → V-08 결과 알림 → 다시 내비 화면
6. **POS P-02에 새 팀 카드 등장** (🚗 4명, 도착 20분 전)
7. (선택) V-09 지연 카드 → 순번 미루기

**도착**
8. V-10 도착 → 하차 확인 중 → "3/4명 하차 확인" + 입장 번호
9. **POS 카드가 "도착 · 3/4명 하차" 초록 배지로** → 점주 [호출]
10. V-11 "입장하세요" 번호표

**재출발**
11. V-12 "B 카페 인원을 3명으로 바꿀까요?" → [바꾸기]

차량 화면과 POS를 **나란히 놓은 분할 프레임**도 시연 영상용으로 1~2장 있으면 좋습니다. 특히 4번(POS 조작 → 차량 알림 숫자 변화)과 9번.
