# 배포 · 데모 · 운영 가이드

> 작성 2026-11-13 · Phase 4 (배포) · Phase 5 (2차 PT) · Phase 6 (전시 운영)
> **Docker 는 쓰지 않는다.** VM 한 대에 JDK 21 + PostgreSQL 17 + Caddy + systemd.

## 1. 구성

```
차량 앱 ─┐                     ┌─ Caddy (443, 자동 인증서) ─▶ 127.0.0.1:8080 Spring Boot (systemd)
POS 웹  ─┴─ https / wss ──────▶┘                                     │
                                                                     └─▶ PostgreSQL 17 (localhost)
```

| 파일 | 하는 일 |
| --- | --- |
| `deploy/setup-vm.sh` | VM 첫 준비 (패키지·DB·계정·`.env` 비밀값 자동 생성·systemd·Caddy·방화벽) |
| `deploy/deploy.sh` | 개발 PC → VM 배포 (테스트 → bootJar → 업로드 → 재시작 → health 확인) |
| `deploy/smartjourney.service` | systemd 서비스 (재부팅 자동 시작, 실패 시 5초 뒤 재시작) |
| `deploy/Caddyfile` | HTTPS + WSS 리버스 프록시 |
| `deploy/nginx-smartjourney.conf` | Caddy 대신 Nginx 쓸 때 |
| `deploy/add-store.sql` | 운영 매장 한 곳 넣기 (PIN 은 bcrypt) |
| `scripts/demo-check.sh` | 데모 직전 점검 |
| `scripts/demo-scenario.sh` | 앱 없이 T1 흐름 9단계 |
| `scripts/load-check.sh` | 접수·현황 p95 측정 |

## 2. 처음 배포 (한 번)

1. **VM 만들기** — Ubuntu 22.04/24.04, 2 vCPU · 2GB 이상. 보안 그룹에서 **22, 80, 443** 만 연다 (8080 은 열지 않음).
2. **도메인** — VM 공인 IP 를 가리키는 도메인. 없으면 `<공인IP>.sslip.io` (예: `3.35.10.20.sslip.io`) 로도 인증서가 나온다.
3. **VM 준비**
   ```bash
   scp deploy/setup-vm.sh deploy/smartjourney.service deploy/Caddyfile deploy/add-store.sql ubuntu@<VM>:/tmp/
   ssh ubuntu@<VM> 'sudo bash /tmp/setup-vm.sh <도메인>'
   ```
4. **배포** (개발 PC, 저장소 루트)
   ```bash
   bash deploy/deploy.sh ubuntu@<VM>
   ```
5. **매장 넣기** — postgres 프로필은 데모 시드를 안 넣는다
   ```bash
   ssh ubuntu@<VM>
   sudo -u postgres psql -d smartjourney -v name='42dot' -v address='경기도 성남시 수정구 창업로40번길 20' \
        -v lat=37.41309722 -v lng=127.09383464 -v pin=1234 -f /tmp/add-store.sql
   sudo -u postgres psql -d smartjourney -v name='소프트웨어드림센터' -v address='경기도 성남시 수정구 창업로40번길 20' \
        -v lat=37.41310555 -v lng=127.094275 -v pin=1234 -v minutes_per_team=3 -v avg_stay_min=40 \
        -v open_time=10:00 -v close_time=22:00 -f /tmp/add-store.sql
   ```
6. **확인**: `bash scripts/demo-check.sh https://<도메인> --reset`
7. 🤝 앱 release APK 의 서버 주소 `https://<도메인>` / `wss://<도메인>/ws`, POS 웹 도메인을 VM `.env` 의 `ALLOWED_ORIGINS` 에 추가 후 `sudo systemctl restart smartjourney`

### 그다음 배포

`bash deploy/deploy.sh ubuntu@<VM>` 한 줄. 스키마 변경은 Flyway 가 부팅 때 적용한다 (`V3__…sql` 추가).

### `.env` (VM: `/opt/smartjourney/.env`, 권한 600)

| 키 | 설명 |
| --- | --- |
| `DB_URL` `DB_USERNAME` `DB_PASSWORD` | setup 스크립트가 만든다 |
| `JWT_SECRET` `QR_SECRET` | 32자 이상 임의 값. 개발용 기본값이면 **부팅 거부** |
| `OPS_TOKEN` | 운영 지표 API·대시보드 토큰. 비우면 KPI 꺼짐 |
| `ROUTE_PROVIDER` `KAKAO_REST_API_KEY` | `kakao` + 키 넣으면 코스 순서 최적화. 없으면 입력 순서 |
| `ALLOWED_ORIGINS` | POS 웹 도메인 (쉼표) |
| `DEMO_ENABLED` | PT·전시 `true` / 실제 매장 `false` |

### 자주 쓰는 명령 (VM)

```bash
sudo systemctl status smartjourney          # 상태
journalctl -u smartjourney -f               # 로그 (토큰·PIN·JWT·QR 은 *** 로 가려짐)
sudo systemctl restart smartjourney         # 재시작
sudo -u postgres pg_dump smartjourney > ~/sj-$(date +%F).sql   # 백업
```

### 시연 순서와 서버에서 일어나는 일

| ① 인원 | 좌석 4 점유 | `POST /journeys` (SENSOR 4) | 차량 "오늘의 탑승 인원 4명" |
| ② 골든타임 | 경로 시작 → ETA 감소 | `GET /stores/{id}/queue-status` + `QUEUE_UPDATED` 구독 | 승인 카드 1회 |
| ③ 접수 | 승인 (터치·음성) | `POST /waitings` (Idempotency-Key = 카드 ID) | **2초 안** POS 에 🚗 4명 카드, 차량 번호·순번 |
| ④ **T2 심사위원 조작** | POS 데모 패널 현장 팀 +3 | `QUEUE_UPDATED` 1회 | 차량 대기시간·골든타임 즉시 변함 |
| ⑤ ETA | 주행 | `PUT /waitings/{id}/eta` | POS "도착 N분 전" |
| ⑥ 하차 | 도착 → 문 열림 → 점유 1 → 문 닫힘 5초 | `POST /arrival` CONFIRMED 3/4 | POS 초록 "3/4명 하차" |

| ⑧ 입장 | QR 확인 → [착석] | `tickets/verify` → `seat` | 카드 사라짐, 여정 다음 매장 |

## 4. 전시 운영 (12월 – 2027.02)

- **지표**: `https://<도메인>/ops/kpi.html` → 운영 토큰(`sudo grep OPS_TOKEN /opt/smartjourney/.env`). 인원 제안 수락률 · 승인 카드 → 접수 · 음성 승인 비율 · 하차 자동 확정률 · 착석/노쇼/취소
- **파기**: 매일 04:30 보유 기간(30일) 지난 기록 삭제. 그날 숫자는 `kpi_daily` 에 보존 → 대시보드 "보존본"
- **커버리지**: `./gradlew test jacocoTestReport` → `build/reports/jacoco/test/html/index.html`
- **외부 웨이팅 플랫폼 제휴 시**: `waiting/platform/ExternalWaitingPlatform` 구현 빈 추가. 커밋된 변화만, 인원·번호표·상태만 넘긴다 (토큰·좌표 없음). 실패해도 우리 흐름은 계속
- **서버를 늘려야 하면**: 지금은 인메모리 Simple Broker (서버 1대 전제). 2대 이상이면 STOMP relay(RabbitMQ 등) + `PinAttemptLimiter` 를 DB 로 옮겨야 한다
